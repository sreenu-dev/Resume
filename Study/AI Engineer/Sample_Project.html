Project Specification

Resilient Enterprise MCP Gateway

User Story

  • As an AI Assistant (LLM) acting on behalf of a user,
  • I want to securely query real-time customer data, order statuses, and inventory levels from distributed enterprise systems using standardized tools,
  • So that I can provide accurate answers without exceeding my context window (token limit) or crashing the downstream internal databases.

Tools Required

  • Claude Desktop App (Free): Acts as your local MCP Host. Point Claude Desktop's configuration file to your locally running C# server to test the live integration.
  • Docker Desktop (Free): To run local infrastructure components (e.g., a local Redis container for distributed rate-limiting).
  • OBS Studio (Free): To record a 2-3 minute demo video of the Claude Desktop app communicating with your local C# server for your GitHub README.
  • Draw.io / Excalidraw (Free): To create high-quality architecture diagrams for your repository documentation, proving your "platform mindset."

Frameworks Used

  • .NET 8 or .NET 9: The core runtime, utilizing modern asynchronous C# patterns (IAsyncEnumerable, async/await).
  • ASP.NET Core: To build the MCP Server implementing the standard JSON-RPC over stdio transport.
  • Polly: A .NET resilience and transient-fault-handling library. Crucial for demonstrating how you protect the LLM from internal API timeouts or failures.
  • System.Text.Json.Schema: For dynamically generating the JSON Schemas that the LLM uses to understand your tools.
  • xUnit & Moq: For enforcing the Test-First/TDD culture highlighted in the job description.

Coding Platform

  • Visual Studio Community 2022 (Free) or Visual Studio Code with the C# Dev Kit extension.

Testing Scope

  • Tool Schema Contract Testing: Unit tests that verify your C# methods correctly output valid JSON Schemas. If a developer adds a new parameter, the test must ensure the MCP tool description updates accordingly.
  • Context Window Protection (Middleware Testing): Write tests that pass a simulated 10MB JSON response from a dummy database. Assert that your MCP truncation middleware intercepts this, trims the array, appends a "truncated": true flag, and returns a safe payload size.
  • Resilience & Timeout Testing: Use Moq to simulate an internal API taking 15 seconds to respond. Assert that Polly intercepts the timeout, cancels the request, and returns a clean, localized error message to the LLM rather than crashing the MCP server.
  • Rate Limiting Logic: Assert that if the MCP server receives more than 5 tool invocation requests per minute for a specific client_id, it rejects the 6th request to protect the backend.

Use Cases

Use Case 1: Safe Data Retrieval (The Truncation Scenario)
  • Action: The user asks Claude, "What are all the transactions for User 123?"
  • Execution: Claude calls your GetUserTransactions tool. Your internal mock database returns 5,000 records. Your adapter slices this to the 10 most recent records, formats them, and returns them to Claude. Claude correctly tells the user the 10 most recent transactions.
Use Case 2: Multi-step Tool Calling (The Agentic Scenario)
  • Action: The user asks, "Check if SKU-999 is in stock. If not, subscribe me to restock alerts."
  • Execution: Claude uses the CheckInventory tool. Your server returns "0 stock". Claude autonomously decides to immediately invoke your second tool, SubscribeToRestockEvent, passing the SKU. Your server acknowledges, and Claude informs the user it is done.
Use Case 3: Graceful Degradation (The Resilience Scenario)
  • Action: The user asks to check an order status.
  • Execution: Claude calls the CheckOrder tool. You simulate a database outage. Instead of a stack trace leaking into the AI's prompt, your Polly implementation catches the error and returns a clean JSON error. Claude reads the error and politely informs the user the system is undergoing maintenance.
