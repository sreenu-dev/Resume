# Google Interview Guide

## Company Overview
- **Focus**: Scalability, algorithms, distributed systems
- **Interview Style**: Algorithm-heavy, system design
- **Difficulty**: Hard
- **Time Limit**: 45 minutes per problem

## Interview Process
1. **Phone Screen** (1 round): 1 medium-hard problem
2. **On-Site** (4-5 rounds):
   - 2-3 Coding rounds
   - 1-2 System Design rounds
   - 1 Behavioral round

## Coding Interview Focus

### Problem Categories
1. **Arrays & Strings** (15%)
   - Complex string manipulation
   - Advanced array techniques

2. **Trees & Graphs** (30%)
   - Graph algorithms
   - Advanced tree problems
   - Topological sort

3. **Dynamic Programming** (25%)
   - Complex DP problems
   - State compression
   - Optimization

4. **Recursion & Backtracking** (15%)
   - Complex backtracking
   - Permutations/combinations

5. **Bit Manipulation** (10%)
   - Bit operations
   - Number theory

6. **Math & Geometry** (5%)
   - Mathematical problems
   - Geometric algorithms

## Interview Tips for Google

### Technical Excellence
1. **Optimal Solutions**: Always aim for best complexity
2. **Edge Cases**: Handle all edge cases
3. **Code Quality**: Clean, readable code
4. **Optimization**: Discuss multiple approaches
5. **Trade-offs**: Explain space-time trade-offs

### Problem-Solving Approach
1. Clarify requirements thoroughly
2. Discuss multiple approaches
3. Analyze complexity
4. Code carefully
5. Test comprehensively
6. Optimize if time permits

### Communication
- Think out loud
- Explain your reasoning
- Ask clarifying questions
- Accept feedback gracefully
- Discuss trade-offs

## Preparation Strategy

### Month 1: Foundation
- Master data structures
- Practice basic algorithms
- Understand complexity analysis

### Month 2: Intermediate
- Solve 40-50 medium problems
- Focus on Google-specific problems
- Practice system design basics

### Month 3: Advanced
- Solve 20-30 hard problems
- Master advanced topics (Trie, Union-Find, etc.)
- Practice under time pressure

### Month 4: Final Polish
- Mock interviews
- Weak area review
- System design practice
- Behavioral preparation
